The big picture

Intel kept improving its chips the way a phone brand releases new models: each is faster, handles more bits and can use more memory, but still runs the programs written for older models. This family is called x86. You mainly compare chips by data-bus width, address-bus width (how much memory), speed and special tricks such as cache and pipelines.

Words you need first

Segment – a block of memory. Cache – a small, very fast memory close to the CPU. Pipeline – an assembly line: the next instruction starts before the previous one finishes. Backward compatible – new chips still run old programs. FPU – the part that does decimal-number maths. Word – the number of bits a CPU handles at once (16-bit, 32-bit…).

Why advanced microprocessors?

Why we needed more

The 8085 is 8-bit and can use only 64 KB of memory. Users wanted more speed, more memory, bigger numbers and many programs at once. So Intel built advanced microprocessors with wider data buses, wider address buses, caches (small fast memory on the chip), pipelining (starting the next instruction before the last one ends) and special modes for multitasking. The x86 family is the line of Intel processors that began with the 8086 and stayed backward compatible (old programs still run on new chips).

8086 internal design

The 8086 has two parts working at the same time: the BIU (Bus Interface Unit) fetches instructions, keeps them in the queue and calculates addresses; the EU (Execution Unit) decodes and executes them. This overlap (pipelining) saves time.

Features of the Pentium

  • Superscalar: two pipelines (U and V) execute two instructions in one clock.
  • Branch prediction: the CPU guesses which way a jump will go (using a branch target buffer) and fetches those instructions in advance; this avoids stalling the pipeline when the guess is right.
  • Separate code and data caches (8 KB each), 64-bit data bus, faster built-in floating-point unit, MMX multimedia instructions in later versions.

Registers and memory in the x86

In simple words

Memory is cut into rooms called segments (up to 64 KB). A location is written as room start : seat number (segment : offset). To get the real address, shift the room start left by one hex digit (multiply by 16) and add the seat number.

Register groups

GroupRegistersUse
General purpose (16-bit; each splits into high/low 8-bit halves)AX (AH, AL), BX (BH, BL), CX (CH, CL), DX (DH, DL)AX = accumulator; BX = base (memory addressing); CX = count (loops); DX = data (I/O, multiply/divide)
Pointer and indexSP, BP, SI, DISP = stack pointer; BP = base pointer (in stack); SI/DI = source/destination index (strings)
SegmentCS, DS, SS, EScode, data, stack and extra segment starting addresses
Instruction pointerIPoffset of next instruction (like PC)
Flags16-bit flag registersee below

Segmented memory: the 1 MB memory is viewed as segments of up to 64 KB. Physical address = Segment × 16 + Offset (shift the segment left by one hex digit and add). Example: CS = 2000H, IP = 0100H → 20000H + 0100H = 20100H.

Flags: status flags (result of an operation): CF carry, PF parity, AF auxiliary carry, ZF zero, SF sign, OF overflow (signed result too big). Control flags (set by the programmer): TF trap (single-step), IF interrupt enable, DF direction (string operations go up or down). From the 80386 onwards the registers become 32-bit (EAX, EBX…, EIP, EFLAGS) and two more segment registers FS and GS are added.
