The big picture

Data is only useful if you can find it quickly. A data structure is the way you arrange it, like arranging a cupboard. An array is a row of numbered lockers. A linked list is a treasure hunt where each clue tells you where the next one is. A tree is an upside-down family tree. For each structure you learn the same jobs: visit every item, search, insert and delete. An algorithm is just a recipe written as numbered steps.

Words you need first

Memory – a long row of numbered cells; each number is the cell’s address. Pointer – a variable that stores the address of another cell. Index – the position number of an item in an array (starts at 0 or 1). Node – one box of data in a list or tree. Recursive – repeating the same rule on smaller and smaller parts. Algorithm – clear steps to solve a problem.

What this chapter covers

Your syllabus list for this chapter covers: introduction, operations, algorithmic notations, control structures, arrays (memory, traverse, insert, delete, sort, binary search, pointer arrays, records), linked lists and binary trees. What is a data structure?

Data and data structures

Data = raw facts (numbers, names). A data structure is a particular way of storing and organising data in the computer so it can be used efficiently. Think of a cupboard: if clothes are sorted on shelves, finding one is quick; if thrown in a heap, it is slow. Goal: save memory and time.

PrimitiveNon-primitive
Basic types the language gives: int, float, charBuilt from primitives: arrays, linked lists, trees, records

Linear structures keep items in a line, one after another (array, linked list). Non-linear structures branch (tree). Static = size fixed in advance (array). Dynamic = size grows and shrinks at run time (linked list).

What can you do with data?

The six operations

  • Traversing – visiting every item once (e.g. to print or add them).
  • Searching – finding the location of an item with a given value.
  • Inserting – adding a new item.
  • Deleting – removing an item.
  • Sorting – arranging items in order (ascending/descending).
  • Merging – combining two sorted lists into one sorted list.

Writing steps clearly: algorithms

What an algorithm is

An algorithm is a finite, step-by-step list of instructions to solve a problem. Properties: clear input and output, each step definite, ends after finite steps. It is written in plain structured English (not a real language) using these notations:

Step 1: Set  K = 1              (assign a value)
Step 2: Read N                  (input)        Write ITEM  (output)
Step 3: If A[K] = ITEM, then ... else ...
Step 4: Repeat Steps 5 to 6 for K = 1 to N
Step 5: Repeat while K ≤ N
Step 6: Exit                    (stop)

Steps are numbered, variables are written in capitals, a name like A[K] means the K-th item of array A, and ← or Set means assignment. Example, sum of N numbers:

1. Read N
2. Set SUM = 0
3. Repeat for K = 1 to N
      Read X;  Set SUM = SUM + X
4. Write SUM
5. Exit

Arrays: a row of lockers

In simple words

An array is a row of lockers numbered 0, 1, 2… Each holds one item of the same kind. Because the lockers sit side by side, the computer finds locker 5 instantly by simple arithmetic. The price: to insert in the middle, everyone after that spot must shift one locker over.

What and how it sits in memory

An array is a collection of same-type items stored in consecutive memory cells under one name, each reached by an index (subscript). LB = lower bound (first index), UB = upper bound (last index), length = UB − LB + 1. Because cells are side by side, the computer can calculate the address of any item:

LOC(A[K]) = Base + w × (K − LB)
Base = address of first item, w = bytes per item

Example: Base = 1000, w = 2 bytes, LB = 0 → LOC(A[3]) = 1000 + 2×3 = 1006

Two-dimensional array (rows × columns) is stored row by row (row-major) or column by column (column-major). Row-major: LOC(A[I][J]) = Base + w × (C × (I − 1) + (J − 1)) for C columns, indices from 1.

Traversing

1. Set K = LB
2. Repeat Steps 3 and 4 while K ≤ UB
3.    Process A[K]                  (print, add, etc.)
4.    Set K = K + 1
5. Exit

Inserting an item at position K (array has N items)

Items from position K onwards must be shifted one place right (starting from the last) to make room.

1. Set J = N
2. Repeat Steps 3 and 4 while J ≥ K
3.    Set A[J+1] = A[J]             (shift right)
4.    Set J = J − 1
5. Set A[K] = ITEM
6. Set N = N + 1
7. Exit

Deleting the item at position K

Items after K are shifted one place left to fill the gap.

1. Set ITEM = A[K]
2. Repeat for J = K to N − 1
3.    Set A[J] = A[J+1]             (shift left)
4. Set N = N − 1
5. Exit

Drawback: insertion and deletion are slow because many items move, and the size is fixed (this is where linked lists help).

Sorting – Bubble sort

Compare each pair of neighbours; swap if the left is bigger. After each pass the largest unsorted item reaches its place at the end. For N items, N − 1 passes.

Start: 5 3 8 1
Pass 1: 3 5 1 8      Pass 2: 3 1 5 8      Pass 3: 1 3 5 8   (sorted)

1. Repeat Steps 2 and 3 for P = 1 to N − 1
2.    Repeat for K = 1 to N − P
3.       If A[K] > A[K+1], then swap A[K] and A[K+1]
4. Exit

Searching – Binary search

Works only on a sorted array. Look at the middle item: if it is the one, done; if the target is smaller, search the left half; if larger, the right half. Each step throws away half the items. (Linear search instead checks one by one from the start and works on unsorted data too.)

Array: 10 20 30 40 50 60 70 ; search 50
BEG=1, END=7 → MID=(1+7)/2=4 → A[4]=40 < 50 → BEG=5
BEG=5, END=7 → MID=6 → A[6]=60 > 50 → END=5
BEG=5, END=5 → MID=5 → A[5]=50 → found at position 5

1. Set BEG = LB, END = UB, MID = (BEG+END)/2
2. Repeat while BEG ≤ END and A[MID] ≠ ITEM
3.    If ITEM < A[MID], then END = MID − 1  else BEG = MID + 1
4.    Set MID = (BEG + END)/2
5. If A[MID] = ITEM, then LOC = MID  else LOC = NULL (not found)
6. Exit

Linear search, selection sort, insertion sort (extra)

Linear search
1. Set K = 1
2. Repeat while K ≤ N and A[K] ≠ ITEM:  Set K = K + 1
3. If K ≤ N then LOC = K (found) else LOC = NULL
4. Exit

Selection sort: in pass P find the smallest of A[P..N] and swap it into A[P].
   5 3 8 1 → 1 3 8 5 → 1 3 8 5 → 1 3 5 8
Insertion sort: take A[K] and slide it left into its place among the sorted items before it.
   5 3 8 1 → 3 5 8 1 → 3 5 8 1 → 1 3 5 8

Pointer arrays

An array whose items are pointers (addresses) instead of values. Example: char *name[3] = {"Ram","Sita","Gita"}; – each item points to a string of different length, saving memory and making sorting easy (swap pointers, not whole strings).

Records and records in memory using arrays

A record is a collection of related items (fields) that may be of different types, describing one entity, e.g. a student: Roll, Name, Marks. A file is a collection of records. Since an array holds only one type, records are stored in memory by using parallel arrays, one array per field, where the same index belongs to the same record:

Index :   1      2      3
ROLL  :  101    102    103
NAME  :  Asha   Ravi   Neha
MARKS :   88     72     95       ← record 2 = ROLL[2], NAME[2], MARKS[2]

Linked lists: a treasure hunt

In simple words

In a linked list the items are not side by side. Each item carries a note saying where the next item is, like a treasure hunt. Inserting is easy: just change two notes. The price: to reach the 5th item you must follow four notes from the start.

What a linked list is

A linked list is a linear collection of nodes where the order is given by pointers, not by position in memory. Each node has two parts: INFO (the data) and LINK (address of the next node). A pointer START (head) holds the address of the first node; the last node’s LINK is NULL (0), meaning end.

START → [ 10 | •]→[ 20 | •]→[ 30 | NULL ]

Representation in memory

Two parallel arrays are used: INFO[ ] for data and LINK[ ] for next-node index, plus START. Unused cells are chained in a free-storage list pointed to by AVAIL; a new node is taken from AVAIL and a deleted node is returned to it.

START = 3
Index :  1     2     3     4     5
INFO  :  30    —     10    —     20
LINK  :  0     —     5     —     1
Read: 3 (10) → 5 (20) → 1 (30) → 0 = end

Operations

  • Traversing: Set PTR = START; while PTR ≠ NULL: process INFO[PTR]; PTR = LINK[PTR].
  • Inserting a node NEW after node P: take NEW from AVAIL, put the data, then LINK[NEW] = LINK[P]; LINK[P] = NEW. Nothing is shifted.
  • Deleting the node after P: LINK[P] = LINK[LINK[P]], and return the removed node to AVAIL.
ArrayLinked list
Fixed sizeGrows and shrinks
Consecutive memoryScattered memory
Insert/delete slow (shifting)Insert/delete fast (change pointers)
Direct access by indexOnly sequential access from START
No extra space for pointersExtra memory for LINK

Types: singly (one LINK), doubly (also a pointer to previous node), circular (last node points back to first).

Trees: a family tree

In simple words

A binary tree is a family tree where each person has at most two children. Traversal just means “visit everyone once”. The three orders differ only in when the parent is visited: pre = before its children, in = between them, post = after them.

What a tree is

A tree is a non-linear, hierarchical structure of nodes joined by edges (like a family tree or folders on a disk).

Terms (each is asked as “define …”)

Root
topmost node, with no parent (50).
Node
one element (data + links to children).
Parent / child
a node directly above / below another (30 is parent of 20 and 40).
Siblings
children of the same parent (20 and 40).
Leaf (terminal node)
a node with no children (20, 40, 60, 80).
Internal node
a node with at least one child.
Degree
number of children of a node; degree of the tree = largest node degree.
Edge / path
edge = line between two nodes; path = sequence of edges from one node to another.
Level
root is level 0 (some books say 1); its children level 1, and so on.
Depth (height)
maximum number of levels from root down to the deepest leaf.
Subtree
a node with all its descendants.

Binary tree

A binary tree is a tree in which every node has at most two children, called the left child and right child (it may also be empty). Kinds: strictly (full) binary – every node has 0 or 2 children; complete – all levels full except maybe the last, filled left to right; binary search tree – left items smaller, right items bigger than the node.

Formulas (depth d = number of levels, counting the root level as 1): maximum nodes at level n (root = level 1) = 2n−1; maximum nodes in a tree of depth d = 2d − 1. So depth 6 → 2⁶ − 1 = 63 (past-paper MCQ: options 64, 63, 31, 127). If the book counts the root as depth 0, use 2d+1 − 1, so check how your textbook defines depth.

Representing a binary tree in memory

1. Sequential (array) representation: put the root in position 1, then number nodes level by level, left to right. For the node at position i: left child at 2i, right child at 2i + 1, parent at ⌊i/2⌋. Empty positions are left blank/NULL (wasteful for lopsided trees).

Index :  1   2   3   4   5   6   7
TREE  : 50  30  70  20  40  60  80     (30 is at 2: children at 4 and 5)

2. Linked representation: each node has three parts: LEFT pointer, INFO, RIGHT pointer; ROOT points to the root; a missing child is NULL. In memory, three parallel arrays LEFT[ ], INFO[ ], RIGHT[ ] plus ROOT and AVAIL are used, like the linked list.

Tree traversals (visiting every node once)

TraversalOrderResult for the tree above
PreorderRoot, Left, Right50 30 20 40 70 60 80
InorderLeft, Root, Right20 30 40 50 60 70 80 (sorted for a BST!)
PostorderLeft, Right, Root20 40 30 60 80 70 50

Remember: the name tells where the root comes: pre = first, in = middle, post = last. Apply the rule to every subtree recursively.
